# 换电脑恢复指南

仓库为公开的考研足迹与项目归档：[Jiang-liran/focus-quest](https://github.com/Jiang-liran/focus-quest)。可以直接查看源码与下载 Release 附件，或从源码构建最新版；读取公开资料无需仓库访问授权。

当前版本为 **1.49.15 / build 80**。主程序支持 macOS 12 以上；当前手机日历辅助程序要求 **Apple Silicon Mac、macOS 14 或以上**。Release 中的旧 app 保持原架构和最低系统要求，选旧版本时应核对相应信息。

## 恢复前准备

先确认 `/usr/bin/python3` 存在。主 app 和后台服务明确使用这个路径，另一个路径的 Python 不会被自动选用。源码构建需要 Xcode Command Line Tools；若新电脑尚未安装，执行 `xcode-select --install`，在系统窗口完成安装，再检查：

```sh
/usr/bin/python3 --version
xcrun swiftc --version
git --version
```

如需保留旧电脑的学习历史和收藏，先做好私人备份。GitHub 不存个人数据库、日历同步配置、快照或番茄账号数据，下载源码或 app 不能恢复这些内容。

旧电脑上，从仓库根目录运行：

```sh
bash outputs/focus-quest/macos/backup-data.sh "/私人备份目录/专注远征备份.sqlite3"
```

脚本通过 SQLite backup API 生成一致副本，服务正在运行时也可备份；它不会覆盖已有同名目标。另行私人保存 `~/Library/Application Support/FocusQuest/calendar-bridge-config.json`，以便在新电脑核对后重新使用。不要把这两个文件放进 Git 仓库。

## 路线 A：从 Release 下载并安装

打开仓库的 [Releases 页面](https://github.com/Jiang-liran/focus-quest/releases)，下载所需版本的主程序 ZIP。通常选最新版 **1.49.15 / build 80**。要使用手机自动同步，还需下载 Release 中单独保存的“专注日历诊断”安装包。

选择准备长期保留的安装目录，例如 `~/Applications`。将下载的 ZIP 解压到该目录；以下用占位文件名表示实际下载的文件：

```sh
mkdir -p "$HOME/Applications"
/usr/bin/ditto -x -k "/实际下载路径/所选版本安装包.zip" "$HOME/Applications"
/usr/bin/codesign --verify --deep --strict "$HOME/Applications/专注远征.app"
```

如果目录内已有同名 app，先退出它，并保留原 app 和私人存档的备份后再更换。80 个原始版本使用同一个 app 名、端口和个人数据目录，不能通过双击多个旧 app 来安全比较版本。

Release 的主 app 内已包含原生可执行文件、Python 和界面资源，不需要重新编译。日历辅助 app 也可同样从其 ZIP 解压安装。

登录后台和私人备份脚本保存在源码仓库。若希望关闭界面后继续自动记录，再克隆仓库取得脚本：

```sh
git clone https://github.com/Jiang-liran/focus-quest.git
cd focus-quest
```

按照下方“恢复私人存档”和“启用电脑后台”操作。若只想先使用界面，在准备好私人存档后直接打开 app 即可；没有注册后台时，原生窗口也能启动本机记录服务。

## 路线 B：从源码构建最新版

```sh
git clone https://github.com/Jiang-liran/focus-quest.git
cd focus-quest
bash outputs/focus-quest/macos/build.sh
mkdir -p "$HOME/Applications"
/usr/bin/ditto -x -k "outputs/专注远征.zip" "$HOME/Applications"
/usr/bin/codesign --verify --deep --strict "$HOME/Applications/专注远征.app"
```

构建脚本根据新 Mac 的架构编译 Swift 窗口，把当前 Python 模块、图标和所有静态资源打入 app，并生成经过签名检查的 ZIP。项目不需要 pip 包、npm 包或 Swift 包依赖。ZIP 默认输出到 `outputs/专注远征.zip`；即使传入自定义 app 输出路径，ZIP 位置仍不改变。

如果要恢复学习存档，先完成下一节；否则可直接启用后台并打开 app。

## 恢复私人存档

私人数据库包含累计学习时间、记录、钱包、收藏、奖励领取状态、目标历史和设置。若没有旧存档，软件会创建一个新存档；重新连接番茄和日历不能完整重建所有奖励、收藏或更早历史。

在首次打开 app 和启用后台前，将旧电脑生成的一致备份放到新电脑的私人目录，然后恢复到：

```text
~/Library/Application Support/FocusQuest/focus-quest.sqlite3
```

对于尚未运行过专注远征的全新电脑：

```sh
mkdir -p "$HOME/Library/Application Support/FocusQuest"
cp "/私人备份目录/专注远征备份.sqlite3" "$HOME/Library/Application Support/FocusQuest/focus-quest.sqlite3"
```

如果新电脑已经运行过软件，先退出主 app 和辅助 app，停止两个登录后台，并备份当前存档，再进行恢复：

```sh
bash outputs/focus-quest/macos/uninstall-service.sh
bash "outputs/手机同步诊断/uninstall-service.sh"
```

不要覆盖运行中的数据库，不要把旧 WAL/SHM 与恢复出的数据库混合。正在运行的 sqlite3 单文件拷贝也不一定完整：最新内容可能仍在 WAL，旧电脑应使用上面的 backup-data.sh。

恢复后检查累计学习时长、近期记录、金币/钻石、收藏和目标历史。日历配置可从私人备份恢复，但新电脑仍要核对本机日历 ID 与权限；旧快照和日志不需要迁移。

## 启用电脑后台与重新连接番茄 ToDo

从仓库根目录安装当前用户的登录后台：

```sh
bash outputs/focus-quest/macos/install-service.sh "$HOME/Applications/专注远征.app"
open "$HOME/Applications/专注远征.app"
```

服务名为 `com.local.focusquest`。它指向这个安装位置的 app；移动或改名 app 后重新执行安装命令更新路径。脚本不会停止占用端口的无关程序，如果提示冲突，先确认端口上的程序。

在新 Mac 安装并登录番茄 ToDo，让它生成本机文件。专注远征默认只读来源：

```text
~/Library/Application Support/tomatodo/tomatodo_db.json
```

在应用的“学习记录同步”检查电脑通道已连接，完成一段新计时并等待约 3 秒确认自动导入。无需将番茄账号数据库上传或从代码仓库取回。第三方应用未来若改变文件格式，需按本机错误信息调整导入适配。

## 恢复 iPhone 日历自动同步

这一路径通过 iCloud 日历同步，不使用番茄账号密码。先在新 Mac 登录手机所用的 iCloud 日历账号，确认系统“日历”中能看到手机番茄记录。iPhone 番茄 ToDo 保持“我的 → 更多功能 → 写入系统日历”开启，并选择两端可同步的学习日历。

如果从 Release 安装，使用其中单独提供的辅助 app。若从源码构建，在仓库根目录执行：

```sh
bash "outputs/手机同步诊断/build.sh"
/usr/bin/ditto -x -k "outputs/手机同步诊断/专注日历诊断.zip" "$HOME/Applications"
```

当前脚本固定构建 `arm64-apple-macosx14.0`；Intel Mac 需要另做目标架构适配和验证。打开辅助 app：

```sh
open "$HOME/Applications/专注日历诊断.app"
```

点击“读取日历列表”，确认 macOS 日历“完全访问”授权，选择正确的学习日历，再读取最近一天检查。辅助 app 只查询，不会创建、改写或删除事件。这个窗口只做诊断，没有自动同步配置保存按钮。

恢复私人保存的 `calendar-bridge-config.json`，或根据本机诊断里的 `calendar.calendarID` 建立配置。日历名字相同不代表 ID 正确，新电脑上应重新核对。配置文件位于：

```text
~/Library/Application Support/FocusQuest/calendar-bridge-config.json
```

配置结构如下；占位内容换成本机日历实际 ID 和完整番茄任务名称：

```json
{
  "schemaVersion": 1,
  "enabled": true,
  "calendarID": "本机选定日历的实际ID",
  "allowedTitles": ["实际任务完整名称一", "实际任务完整名称二"],
  "lookbackDays": 90
}
```

白名单按完整名称精确匹配。避免在这个日历中用同样名称建立普通计划，否则仅凭名称和时间无法区分。诊断文件位于个人数据目录中的 `calendar-diagnostics/`，可能含事件和备注，只在私人位置保存，不能上传仓库。

授权和配置完成后，安装日历后台服务，再退出辅助 app 的前台窗口：

```sh
bash "outputs/手机同步诊断/install-service.sh" "$HOME/Applications/专注日历诊断.app"
```

服务名为 `com.local.focusquest.calendarbridge`。约 30 秒后，在主 app 的同步面板检查手机通道；“立即同步”可请求提前读取。iCloud 把手机事件送到 Mac 的时点不受本程序控制，电脑睡眠或关机期间也不能采集。恢复运行后会检查最近 90 天仍在日历中的匹配事件，未写入日历的旧记录依赖私人存档备份。

## 检查与后续更新

```sh
launchctl print "gui/$(id -u)/com.local.focusquest"
launchctl print "gui/$(id -u)/com.local.focusquest.calendarbridge"
curl --fail http://127.0.0.1:18473/api/health
```

分别完成一段电脑记录和手机记录，确认自动更新；重复刷新不应重复累计。关闭主窗口后，登录后台仍可采集。连接失败按 ⌘R 重试，查看 `~/Library/Application Support/FocusQuest/` 中的 `server.log`、`service.log` 或 `calendar-bridge.log`。

日历权限报错时，先停日历后台，打开辅助 app 重新授权，再安装后台；移动两个 app 后也要分别重新安装服务。之后更新源码需要重新构建和安装，Git pull 不会自动替换已安装 app。

开发测试需要支持 Node 内建测试器的 Node，测试数据写在临时目录：

```sh
cd outputs/focus-quest
/usr/bin/python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/test_*.cjs
```

历史版本的恢复和隔离查看方法见[版本恢复说明](版本恢复说明.md)。
