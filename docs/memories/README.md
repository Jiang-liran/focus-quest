## 如何继续记录

每个软件版本使用一个目录：

```text
docs/memories/
├── README.md
├── _templates/
│   └── version.md
└── <整理日期>-v<version>/
    ├── README.md          # 版本摘要、真实学习记录、日期和来源
    └── screenshots/
        ├── 01-home.png
        ├── 02-review.png
        └── 03-feature.png
```

项目更新时从[记录模板](_templates/version.md)新建档案，优先留存几张真实学习画面和可核对的积累，也可补充本版新增的功能。首页四科与星岛、学习复盘或专注星历，都是可用入口；无需为凑齐模块或数量重建不存在的经历。补充同一版本的资料继续放在原目录，并注明新的整理日期，不增加软件版本号。

每张图写清楚“展示什么、何时截取、画面属于哪一天或哪段时间、资料来自哪里”。真实学习画面可记为“真实学习”；测试、模拟或重建画面必须记为“测试/演示数据”，不能用来说明用户学了多久。截图日期与学习日期不同，要分别记录；不能确认的日期写“未知”。

努力记录可以是一句用户自己的回顾，也可以是截图中可核对的四科或某个周期汇总。数字照资料填写，注明范围和统计口径；目标、奖励、收藏、小游戏结果和软件测试数量不代表学习小时或学习质量。原话注明来自用户，不代写用户没有说过的感受。

本次授权允许将精选真实学习截图和可核对汇总存入此私有仓库。上传前移除无关身份信息与通知。原始数据库、日历/同步数据、账号配置和令牌、私人完整备份继续保存在仓库之外；本目录用于回看，存档恢复请见[换电脑恢复指南](../换电脑恢复指南.md)。

历史版本的功能事实可引用[版本索引](../版本索引.md)、使用说明及对应源码。80 版恢复快照的整理日期不代表当年的开发日期，今天截取旧版界面也不代表当时的学习状态。资料缺失就注明缺失；以后有了可靠来源，再补进来。

本目录与项目更新一并提交、推送。正式版本的源码、标签和安装包入口由每版 README 链接到 GitHub；仅在本机保存的资料不能写成已经上传。
