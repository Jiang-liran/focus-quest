# 专注远征便携备份测试适配记录

本次备份整理仅适配测试夹具路径、测试时钟和已有票券机制的初始化假设。114个运行源文件与已发布v1.49.15全部逐字节一致，安装软件、个人学习存档和运行行为不变。所有测试使用临时数据库和人工测试记录。

第一次全量验证运行619项Python测试，出现4项失败和1项错误。逐项核对业务源码后，确认原因是旧测试未计入后来新增的持久游玩券初始化/记账，或把`datetime`类型换成普通mock；没有发现需要修改业务源码的缺陷。

## 适配依据

`FocusStore.__init__` 不执行首次游玩券初始化。`state()`、`lottery_state()`和`import_sources()`会调用`_sync_play_tickets()`；首次调用会保存`PLAY_TICKETS_START_META`、当天`arcade_ticket_earnings`基线以及相应记录信用，再增加一次全局`revision`。即使没有赚取任何游玩券，也需要持久保存当天零券基线。此行为可以在`server.py`的`state`、`import_sources`和`_sync_play_ticket_issuance`中直接核对。

| 测试 | 原失败原因 | 具体适配与保留的验证 |
| --- | --- | --- |
| `test_city_life.test_outfit_can_save_every_owned_slot_and_apply_atomically_without_currency` | 应用装扮的返回结果读取`quest_state → lottery_state`，首次创建当天游玩券基线，发生在数据库快照之后。 | 保存操作前先调用`lottery_state(NOW)`完成正常初始化，再取完整快照。保留全部数据库快照、装备、零货币及重启幂等断言，没有排除游玩券表或`meta`。 |
| `test_goal_history.test_historical_matching_is_read_only_and_consistent_in_all_periods` | 历史读取最后调用`state()`时首次创建游玩券基线，不能与未经初始化的快照直接比较。日志中的日期等于测试固定的`NOW`，不是系统日期漂移。 | 在既有重启步骤之后、完整快照之前调用`lottery_state(NOW)`。保留周/月/年历史一致性、完整数据库未变以及重启后快照未变等全部断言。 |
| `test_upgrade.test_old_archive_settings_migrate_and_preserve_records` | 测试在导入学习记录后、票券信用首次初始化前保存`revision`；迁移之后第一次`state()`又完成初始化，正常增加一次版本号。 | 导入测试记录后先调用原有`self.state()`辅助方法，再注入旧设置并保存迁移基线。保留旧设置、历史目标、45分钟记录、严格版本号相等及二次重启设置一致断言。 |
| `test_live_capture.test_real_poll_new_task_exactly_once_and_restart_persistence` | 每次新记录同步包括一次记录导入和一次持久票券信用记账，全局`revision`应精确增加2次，而旧断言只计入导入一次。 | 严格断言改为`initial.revision + 2`，没有使用范围或不等式。新增票券累计分钟从30到45、票券余额始终1的断言；重复源记录及重启后仍精确等于45分钟信用、1张券与原版本号，继续保证没有重复导入/记账/发券。 |
| `test_idle_sync.test_calendar_freshness_crossing_is_not_hidden_by_cache` | `patch.object(server, 'datetime')`生成普通mock，后来`quest_clock`的`isinstance(current, datetime)`要求第二参数是类型，因此抛出`TypeError`。 | 使用真正继承`datetime`的测试时钟，只覆盖`now()`，通过继承的`fromtimestamp()`构造指定未来时刻。保留标准构造器与类型语义，以及日历变为不新鲜、源缓存失效的原有严格断言。 |

这5项适配没有删除任何断言。快照测试仍比较完整原定范围，导入测试额外验证了持久票券记账不被重复同步或重启重复执行。
